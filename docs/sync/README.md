# docs/sync · 两个 agent 之间的交接协议

这个仓库上同时有两个 agent 在改代码：**Qoder（`C:\Users\dong\.zcode\...` 那份工作树）** 和
**WorkBuddy（`C:\Users\dong\Documents\GitHub\...` 那份，负责发布）**。两者不能直接对话
（实测：Qoder 的会话列表里没有 WorkBuddy；它的本地日志只有调用帧、没有正文；未识别的本地端口不去请求，
因为那是以发起人身份行事）。所以这里只放**能留下产物的**交接方式。

**为什么不用互发消息：** 今天抓到的每一个错都来自读产物，不是来自被告知。
`63x` 是自己量出 5.8x 的；「不另升版本」是自己对比 bundle 哈希才发现前提废了；
`4da1190` 那处邮箱泄露是 WorkBuddy 复核自己的清单抓的。两个 agent 直接对话不产生可查的东西。

## 五条规则

1. **关于 commit 号 / 版本号 / 线上状态的条目，写之前必须重新取数**（`git fetch` + 两个 `rev-list --count`
   + `curl ... | grep app-version`），并把**取数时刻和原始输出**贴进条目。
   禁止用记忆里的状态写现状 —— 本小时内就发生过：我说「三方对齐在 `dc85da6`」时它已经不成立，
   版本从 0.8.4 走到 0.8.5、master 又前进一个提交。
2. **写不出 falsify 命令的条目，status 只能是 `转述待证`，且不得被引用为已证。**
   现存例子：「CI 首次全绿」—— 私有仓匿名 API 404、会话里没有 `gh`，谁也读不到日志。
3. **只追加，不删别人的条目；而且一个条目只能由它的作者写。** 收口是在下面加一行 `re:`，注明你怎么验的、
   结果是原话还是反驳。观察到对方做了某事，要写成「我观察到 X 做了 Y（引 commit）」，
   **不能代对方起草主张** —— 那等于给对方安上他没说过的话，也正是这个文件要防的事。
   （本文件建起来时我就犯了这一次，已改成 `Qoder 记录（引 commit 4da1190，非 WorkBuddy 所写）`。）
4. **自己写错的保留原文 + 加更正行，不抹掉。** 已经这么做过两次（CHANGELOG 里那句版本判断、
   下面 #2 条的邮箱漏检）。抹掉等于让同一个错有机会再犯一次。
5. **两个 agent 都不得替发起人做**：花钱的模型调用、发布、转公开、force push、
   以及往这个仓库写会进公开历史的工具产物（例：`code-review-graph install` 会新建
   `QODER.md` 并修改 `.gitignore`，别跑）。
6. **版本号只由 WorkBuddy 单点升**（发布归它，版本就归它）。Qoder 侧不碰 `package.json` 的
   `version`；需要新代际时在 INBOX 点名要求，由 WorkBuddy 在发布那一笔里连同 `package-lock.json`
   一起升（锁与版本不一致会让 `npm ci` 第一步就死，已有断言守着）。
   为什么定死：**同一条链上两边各升过一次**（`dc85da6` 升 0.8.4、`4da1190` 升 0.8.6）这次侥幸没撞，
   但「不升版」的判断一旦基于对方会不会升，就会写成假话 —— 我已因此写过一次「行为不变、不另升版本」，
   两小时后被并行发布作废。单点写，规则就不需要猜。
7. **改这个文件只用追加，且插入位置要能证明没吃掉别人的条目**：`git diff --numstat` 必须是
   `N 0`（0 删除）。2026-09-28 我插 #12 时用整段锚点做替换，**把 WorkBuddy 的 #11 标题行删掉了**，
   靠这条检查才发现并还原。
8. **发布源那份 clone（`Documents\GitHub\internship-workbench`）只由发布方读写。** 另一个 agent
   不在那里 `pull` / `fetch` / `build` —— 需要它到某个提交时，在 INBOX 里写清楚由发布方去拉。
   起因：我为了"对齐"在那里跑过两次 `git pull --ff-only`，WorkBuddy 在 #12 的 ④ 观察到
   "发布源被外部 pull 推进过"却不知来源。来源是我。后果本来不严重，但它落在
   **"读到线上版本 → 打包上传"之间就是竞态**：可能发出与报告不同的构建。
   同一条理由也解释了为什么**取号前必须先 fetch** —— 我 #13 那条就是没 fetch 就占了 `#12`，撞号、冲突、push 被拒。

## 条目格式

```
### <日期 时刻> · <谁> → <谁> · #<序号>
claim:    一句话主张
falsify:  能推翻它的命令（或写「无」-> 那 status 只能是 转述待证）
status:   已自证 | 转述待证 | 未证不可引用
need:     对方要做什么（没有就写 无）
evidence@<取数时刻>:  原始输出，不加工
```
