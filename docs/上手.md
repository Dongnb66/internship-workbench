# 上手 · 5 分钟看到东西，然后让岗位自己进来

> 面向第一次打开这个工作台的人。按钮名称都是界面原文，流程按仓库实况写——包括哪些路当前走不通，也照实说，不美化。

## 一、先 3 步：3 分钟内看到东西

1. 打开线上地址 **<https://internship-workbench-47024.app.workbuddy.host/>**，填邮箱 → 收验证码 → 进去。不用注册密码，新邮箱会自动开号。
2. 左侧「岗位」→「岗位池」→ 点「**+ 新增岗位**」，把一个你正在看的岗位录进去（公司、岗位名，JD 整段粘上）。
3. 回到岗位池列表，它就在了。匹配度会按你「目标条件」里的画像自动算。

到这一步，你已经有了一条不会丢的线索。**不想手动录？两条替代入口：**

- **岗位广场**：左侧「岗位」→「岗位广场」，这是所有人共享的公共岗位库，挑中意的点「加入岗位池」复制进自己的池子，零成本。注意它的内容是服务端一次性灌入的，新鲜度取决于最后一次灌入时间。
- **浏览器扩展**：`chrome://extensions` → 开发者模式 → 加载已解压的扩展程序 → 选仓库的 `extension/` 目录。之后在任意招聘结果页点扩展里的「**采集本页岗位**」→ 结果自动复制 → 回「岗位池 → 批量导入」粘贴 → 核对入库。它只读当前这一屏的 DOM，不发网络请求。

## 二、让岗位自己进来（本地抓取器）

先说清一个设计，免得你在网页上找半天按钮：

**网页端不跑爬虫——抓取永远发生在你自己电脑上。**「抓取任务」页给两条路：**一键抓取（本地助手）**——你在本机跑一个小助手（`npm run agent`，只监听 127.0.0.1），网页就能勾站点点「开始抓取」，日志实时滚动、跑完自动弹出入库预览；**生成命令**——页面生成一条 `node run.mjs …` 命令，你自己开终端粘贴运行。这是有意的：服务端不拿你的账号去爬——风控后果（限流、封号、验证码升级）落在谁头上，就由谁按那个按钮。本项目线上只有静态站点 + 云数据库，没有常驻进程，服务端抓取在架构上就没有落点。一键不想配、或要抓「指定地址」类站点（一键带不了它们）时，用命令方式；完全不想碰终端的话，用第一节的三条入口就够了。

**路线 A · 一键抓取（推荐，配一次小助手）**

1. 在项目根目录开一个终端跑 `npm run agent`（本地助手，只监听本机 127.0.0.1，不对外）。
2. 网页「岗位 → 抓取任务」→ 等它探测到「**本地助手已连接**」（没连上点「重新检测」）。
3. 勾站点、填岗位关键词 → 点「**开始抓取**」→ 日志实时滚动，跑完自动弹出导入预览。
4. **逐条核对** → 勾选入库。

**路线 B · 生成命令（要开终端）**

1. 网页「抓取任务」页 → 选站点、填岗位关键词 → 点「**复制命令**」（生成的形如 `node run.mjs --site tencent --keyword 前端`）。
2. 开一个终端（Windows 用 PowerShell 就行），cd 到仓库的 `crawler/` 目录。
3. 第一次要先 `npm install`（只装 playwright-core，不下载浏览器内核；它驱动你系统已装的 Edge / Chrome）。注意这只够默认引擎用：BOSS 直聘那条路走的是 scrapling 引擎，还要另装 Python + scrapling（独立 venv，照 `crawler/README.md`「装什么」一节做）——不抓 BOSS 就不用装，默认路径完全不依赖 Python。
4. 粘贴命令 → 回车 → 等。默认翻 2 页、请求间隔 2.6 秒 + 随机抖动，再逐个打开岗位详情页补 JD（默认前 20 条，`--detail` 可调）。
5. 回网页 →「岗位池」→「批量导入」→「**选择抓取结果文件**」→ 选 `crawler/output/<站点>-<时间>.json`。

导入走「直读、不过模型」那条路，不消耗 AI 额度。**核对那一步不能省**：程序读不到的字段就是空的，它不会替你猜。

### 选站点之前，先看状态标注（照实说）

「抓取任务」页每个站点都带标注。**各站点当前能不能爬，以每个站点旁的标注为准**（实测可用 = 真跑通过 / 实测抓不到 = 当前技术栈下拿不到），逐条实测结论见 `crawler/README.md`：

| 标注 | 意思 | 你该怎么做 |
| --- | --- | --- |
| 实测可用（live） | 真跑通过，且逐条核对过抓到的确实是岗位名 | 直接用。当前 6 个：腾讯、美团、中兴、拼多多、海康威视、科大讯飞（合计已验 41 条）；BOSS 直聘也已实测跑通，但只在换引擎那条路成立，见下方第一条特别提醒 |
| 未验证 | 管线在，但没打过真实站点 | 可以试。第一次跑先 `--pages 1 --detail 0` 小量探路，能读到再加量；第一次失败很正常 |
| 实测抓不到（offline） | 真跑过，当前技术栈下拿不到岗位 | **别白试**。当前 5 个：招商银行、华泰证券、顺丰、比亚迪、联想（原因都写在 crawler/README.md） |

两个特别提醒：

- **BOSS 直聘：默认内核下仍然进不去，自动化要走换引擎那条路。** 它挂了专门的浏览器检测 SDK（browser-check-v2.js），在本地抓取器的 Playwright 技术栈下连登录页都进不去，渲染出来的 DOM 只剩 8.5KB 空壳、0 张岗位卡；换真 Edge 内核、抹 `navigator.webdriver`、换 UA 都试过，全部无效。它现在标「实测可用」，但**要在 scrapling 引擎下跑才成立**（可选的反检测引擎，要装 Python；安装、扫码登录、单轮页数建议见 `crawler/README.md`「BOSS 直聘：默认内核拿不到，要换 `scrapling`」一节）。不带 `--engine` 也能直接跑：程序按站点表声明自动路由（BOSS 在 `crawler/sites.mjs` 里声明了 `engine: 'scrapling'`），`--engine <名字>` 只是显式覆盖开关；引擎环境没装时只判停这一站、其余站点照跑，退出码非零——不会静默给你 0 条。默认也不解薪资：带字体混淆的薪资一律留空，要解另有显式开关、默认关闭，同见 README。
- **要 BOSS 的岗位，浏览器扩展仍然更快更稳**：在 BOSS 页面点「采集本页岗位」——读的就是你自己看得见的那一屏，不用装 Python、不用换引擎。
- **关键词只对带 🔍 的站点生效**（腾讯 / 字节 / 实习僧 / BOSS）；其余站点是固定入口页，整页抓取，关键词会被忽略。没有独立入口的托管平台（飞书 / 北森 / Moka）用 `--url` 直接给目标公司的招聘页地址。

### 需要登录的站点

站点表里带 🔒 的要先自己登录一次：

```bash
cd crawler
npm run login -- --site <站点id>    # 弹出独立窗口，你自己登录（含扫码/短信）
```

登录态存在 `crawler/.profile`（已在 .gitignore 里，不影响你日常浏览器），抓取器只复用会话，全程不读取、不上传 cookie 内容。想清掉登录态就删 `.profile` 目录。

BOSS 用不了上面那条 `npm run login`（那条路走默认内核，BOSS 要走 scrapling 引擎）：登录用 `node run.mjs --site boss --login`（不带 `--engine` 也会按站点表自动路由到 scrapling；弹出独立窗口，你自己扫码）。它的登录档案存在 `crawler/.profile-scrapling`，和默认内核的 `.profile` 不通用。

## 三、常见卡住的地方（症状 → 原因 → 怎么办）

| 症状 | 原因 | 怎么办 |
| --- | --- | --- |
| 命令跑了，输出 0 条 | 站点要登录；或 SPA 渲染慢没等够；或页面结构与预期不同 | 先加 `--wait 6000`；还不行就 `--dump` 存渲染快照看（第一招），或 `--headed` 亲眼看一遍 |
| 输出「没有更多可翻的页了，停止」 | 正常——这个站就一页结果 | 不是故障，继续下一个站 |
| 输出「第 N 页命中安全停止清单（验证码/登录墙/风控拦截）」 | **正常且是刻意的**：项目遇到验证码会主动停本站，不重试、不绕过 | 当天别再对这个站跑了；换站点，或用扩展手动采 |
| 「没有可用的浏览器」 | 上次抓取被强杀，`.profile/lockfile` 残留 | 加 `--profile <别的目录>` 绕开（代价：登录态要重登） |
| 导入时提示「这段 JSON 里没有识别到岗位」 | 选错文件，或产出本来就是空的 | 确认选的是 `crawler/output/*.json`；扩展采集的结果用弹窗里的「复制 JSON」 |
| 导入时提示文件太大 | 岗位文本不会有几百 MB——基本是选错了文件 | 回 `crawler/output/` 重新选 |
| `localhost:5173` 只能看到登录页、收不到验证码 | 邮箱验证码登录只在正式发布域上可用（服务端校验 Origin），本地预览收不到 | 直接用线上地址；本地开发见 `docs/QUICKSTART.md` 第 4 步 |
| AI 功能点了没反应 | 默认不花创建者的钱：要自备 Key 或用本机模型 | 「目标条件」→「AI 通道」→ 配 DeepSeek / Kimi / 百炼等自己的 Key（智谱实测发不出去），或装 Ollama 后选「本机 Ollama」（不花钱） |
| 抓到的薪资/数字变成「口口口」空框 | 该站对列表页做了字体反爬（数字被换成私有区码位） | 薪资里有一部分站点做了字体混淆（数字在源码里不是数字）。**本项目默认不去解它** —— 那属于破对方专门用来拦抓取的保护措施。**要薪资就明确选一条路**：用浏览器扩展在你自己登录的页面里采集，或在岗位详情里手动补。抓取器默认把这类值**留空**，不会给你猜出来的数字。**（抓取工具另有一个显式开关可以解这层映射，默认关闭；细节见 `crawler/README.md`。）** |

## 四、它整体怎么运转

```
浏览器（React SPA，线上托管）
   │
   ├── 云服务后端（DB / Auth / LLM）        ← WorkBuddy 平台，无自建服务器
   │
浏览器扩展 ──采集当前页（activeTab，不发网络请求）──▶ 岗位池（批量导入粘贴）
   │
本地助手 crawler/agent（npm run agent，只监听 127.0.0.1）
   └── 网页「一键抓取」直连它：勾站点 → 开始抓取 → 日志实时回显 → 弹出导入预览
       │
本地抓取器 crawler/（跑在你电脑上，Node + playwright-core 驱动已装的 Edge/Chrome）
   └── 真浏览器 ──▶ 27 个招聘站 ──▶ output/*.json ──▶ 回网页「批量导入」──▶ 岗位池
```

岗位来源一共四条路，区别只是「谁来点」，读的都是浏览器**已经渲染出来的 DOM**，都不调平台接口、不绕登录/验证码：

| 通道 | 自动化程度 | 跑在哪 |
| --- | --- | --- |
| 岗位广场 | 点一下「加入」，零成本 | 公共库（服务端灌入） |
| 整段粘贴 → 结构化 | 全手动 | —（连扩展都不用装） |
| 浏览器扩展 | 手动点一次，读完当前这一屏 | 你的浏览器 |
| 本地抓取器 `crawler/` | 自己翻页 + 逐个补 JD，可断点续跑 | 你自己的机器 |

更完整的手绘架构图见 [`architecture.html`](architecture.html)。
