## 1. 引言

### 1.1 文档目标

- **一句话定位**：本文档定义**实习管理工作台（internship-workbench）** 在交付物中的所有架构设计相关产物。
- **读者对象**：架构师 / 开发 / 运维 / 安全 / 评审委员会。
- **设计范围**：业务架构 + 应用架构 + 数据库设计 + 部署架构 + 网络架构 + 安全设计 + 可观测设计。
- **设计原则（继承上游冻结边界）**：AI 只做辅助、发送键始终由人按；不做自动投递 / 自动发送（经中间确认 X7，用户裁决）；不绕验证码 / 风控 / 登录墙；不做检测规避。
- **部署形态锚定（经用户 2026-09-29 G4 裁决 X9）**：部署形态维持多用户公网 BaaS（单 AZ，MVP），不收敛为单用户私有。

### 2.2 领域关系映射

#### 2.2.1 限界上下文清单

| 限界上下文 | 对应业务域 | 域类型 | 覆盖的核心业务实体 | 上下文边界（属于本域 vs 不属于） |
| --- | --- | --- | --- | --- |
| `JobPool-BC` | 岗位获取域 | 支撑域 | O-01 `Job` / O-02 `PublicJob` | 属于：岗位快照字段、去重键、渠道能力边界；不属于：评分结果、投递状态 |
| `Scoring-BC` | 评分决策域 | 核心域 | O-09 `AiReport` | 属于：本地预筛分、七维评分、评分依据；不属于：岗位原始字段、投递动作 |
| `Pipeline-BC` | 投递跟进域 | 支撑域 | O-03 `Application` / O-04 `Message` / O-05 `Interview` / O-06 `Offer` | 属于：阶段流转、会话时间线、面试记录、Offer 对比维度；不属于：岗位评分、简历文件 |
| `Agent-BC` | 求职智能体域 | 核心域 | O-08 `Task` | 属于：ReAct 步骤、行动清单、逐步审计轨迹；不属于：直接写业务表（只读业务数据、只产出建议与任务记录） |
| `Asset-BC` | 个人资产域 | 支撑域 | O-07 `Resume` / O-10 `Knowledge` / O-11 `Profile` | 属于：简历附件、知识条目、目标条件与节奏；不属于：岗位数据、投递数据 |
| `Platform-BC` | 平台底座域 | 通用域 | 账号身份 / 会话 / 配额 / 站点表 | 属于：认证身份、RLS 隔离策略、LLM 通道、采集器站点表；不属于：任何业务语义 |

**域类型说明**：

| 域类型 | 含义 | 投入策略 |
| --- | --- | --- |
| 核心域（Core） | 业务护城河，差异化竞争力所在 | 投入最多资源自研（`Scoring-BC` 可解释评分、`Agent-BC` ReAct 巡检） |
| 支撑域（Supporting） | 必要但非差异化 | 可自研可外采（`JobPool-BC` / `Pipeline-BC` / `Asset-BC`） |
| 通用域（Generic） | 通用能力（账号中心、LLM 通道等） | 优先复用 / 外采（`Platform-BC` 复用 WorkBuddy 云服务） |

#### 2.2.2 上下文映射（Context Mapping）

| 关系编号 | 上游上下文 | 下游上下文 | 关系模式 | 同步方式 | 选择理由 |
| --- | --- | --- | --- | --- | --- |
| C-01 | `JobPool-BC` | `Scoring-BC` | Customer/Supplier | API 同步 | 评分为岗位池下游，岗位快照字段（`dedupe_key` / 岗位正文）须按评分需求稳定供给 |
| C-02 | 招聘平台页面 / OfferBiu / ATS | `JobPool-BC` | ACL 防腐层 | API + 适配器 | 外部 DOM / 异构 JSON 经 `collector.js` + `normalize.mjs` 归一（O-15 `JobFeedAdapter`），外部模型不污染本域 |
| C-03 | 全部业务上下文 | `Platform-BC` | Shared Kernel | 云 SDK / 共享常量 | `owner_id` 隔离字段与 `GREETING_RULES` 数字口径必须全局一致，共享内核最小化 |
| C-04 | WorkBuddy 云服务 | 全部业务上下文 | Conformist | 遵循平台模型 | 无议价能力的强势平台底座，直接遵循其 PostgREST 表 / 认证 / LLM 模型 |
| C-05 | `Scoring-BC` | `Agent-BC` | Published Language | 只读查询契约 | 评分报告以稳定字段集对外暴露，供智能体与看板多个下游共同消费 |

**关系模式说明**：

| 关系模式 | 适用场景 |
| --- | --- |
| Customer/Supplier | 上下游强协作，下游能影响上游迭代节奏（岗位池 → 评分） |
| Conformist | 顺从者，下游完全遵循上游模型（本系统对接 WorkBuddy 云服务） |
| ACL（Anticorruption Layer） | 在本域和外部域之间建适配层，外部模型变化不影响本域（对接招聘平台 / OfferBiu / ATS 时必用） |
| Shared Kernel | 共享内核，多个上下文共享一小块代码 / 模型；维护成本高，慎用（`owner_id` 契约、数字口径常量） |
| Published Language | 上游以标准协议（事件 / Schema）对外暴露，多下游消费（评分报告只读契约） |
| Open Host Service | 上游提供标准 API 接口，类似 Published Language 但通过 RPC |

#### 2.2.3 跨域协作原则

| 原则编号 | 原则 |
| --- | --- |
| P-01 | 核心域 → 支撑域 / 通用域：禁止反向依赖（`Scoring-BC` / `Agent-BC` 不依赖支撑域内部模型） |
| P-02 | 核心域之间：`Scoring-BC` 与 `Agent-BC` 禁止直接耦合，必须通过 Published Language（C-05 评分报告只读契约）解耦 |
| P-03 | 对接外部不可控系统（招聘平台 / OfferBiu / ATS）：必须建 ACL 防腐层（C-02），禁止把外部模型贯穿到本域 |
| P-04 | 全部业务上下文对 `Platform-BC` 的 RLS 隔离字段 `owner_id` 只读遵从，前端写操作一律不传 `owner_id`（D8 §3 不变量） |

#### 3.1.4 工程结构

本系统**无自建后端**：后端为 WorkBuddy 云服务（BaaS），业务逻辑集中在 `src/lib/` 纯函数层，数据访问唯一出口 `src/lib/api.ts`；多端各自独立工程，共用同一套云后端与同一批表。公共纯函数模块被多端依赖，禁止公共模块反向依赖页面。

```

│   ├── lib/                   # 纯函数业务层（与 React 解耦，now 可注入）

│   │   ├── agentTools.ts      # 工具注册表
│   │   ├── quota.ts           # 配额三闸
│   │   ├── untrusted.ts       # 外部文本隔离三道防线
│   │   ├── factGate.ts        # 事实守门
```

#### 3.5.2 幂等性约定

| 接口类型 | 是否要求幂等 | 幂等键来源（建议） |
| --- | --- | --- |
| 写入类（POST 创建） | 涉及通知 / 配额 / 记录类"重复执行有副作用"的，**必须幂等** | Header `biz_req_no`（调用方生成）或业务唯一键 `dedupe_key` |
| 更新类（PUT / PATCH） | 必须幂等 | 资源 ID + `version`（乐观锁） |
| 删除类（DELETE） | 天然幂等 | — |
| 查询类（GET） | 天然幂等 | — |
| 配额 / 通知 / 巡检类 | **强制幂等** | 业务侧请求号（`biz_req_no`，巡检按"当日"唯一） |

**幂等设计需考虑的问题**：

| 问题维度 | 设计要点 |
| --- | --- |
| 幂等键的生命周期 | 短期防抖（会话内）与长期对账（配额台账按日）分开保留 |
| 重复请求的语义 | 写入类返回首次结果；巡检类返回同一 `Task` 不重复建 |
| 执行中态的处理 | 巡检类若已有 running 任务，第二个请求复用而非拒绝 |
| 失败请求的可重试性 | 系统错误允许同键重试；业务错误（配额 / 校验）不允许 |
| 存储兜底 | `dedupe_key` 与 `biz_req_no` 落库唯一索引作为最终防线 |

## 4. 数据库设计

> **本章回答**：每个模块的状态用什么表存、表怎么建、数据怎么清理、缓存怎么用。
> **核心方法论**：**数据库按业务域组织，业务域与第 2 章 / 第 3 章保持一致**，禁止按"用户表 / 订单表 / 日志表"这种横向技术维度组织。

### 4.1 全局数据约定

| 约定项 | 取值 | 说明 |
| --- | --- | --- |
| 命名规范（表名） | 小写名词复数，无前缀 | 沿用既有 11 张表基线（`jobs` / `applications` / ...），不引入 `t_` 前缀以避免全库重命名返工 |
| 命名规范（字段名） | 小写 + 下划线（snake_case） | 禁止驼峰 |
| 主键类型 | UUID（字符串主键 `id`） | 全项目统一，平台生成，禁止混用自增 |
| 字符集 / 排序 | utf8mb4 / utf8mb4_unicode_ci | 支持 emoji 与多语言 |
| 时间字段类型 | timestamptz（UTC 存储，ISO 8601 序列化） | 统一精度与时区；前端展示走 `format.ts` |
| 软删除字段 | 通过 `stage` / `status` 归档，不做行级软删 | 既有实现选择，简化 RLS 与索引 |
| 审计字段 | `created_at` / `updated_at` | 由平台自动维护，命名锁定 |
| 隔离字段（多租户） | `owner_id`（uuid NOT NULL） | 多租户必备；RLS 强制 = `auth.uid()`；查询与写入必带 |
| 业务唯一标识 | `dedupe_key VARCHAR(200)` | 岗位与投递去重；跨端逐字一致 |
| 状态枚举 | `VARCHAR` 字符串 | 二选一锁定为字符串；DDL 注释列出全部取值 |
| 金额字段 | 无（本项目不含资金流） | — |
| 手机号存储 | 不落库 | 认证由平台托管，项目库不含手机号明文 |

### 4.4 缓存与 Key 规范

> 本系统**不使用服务端 Redis 缓存**，本节承载"**客户端本地缓存与 Key 规范**"——`localStorage` / `chrome.storage.local` / 本机去重历史文件的命名与 TTL 约定，它们是"分布在本机的隐形数据库"。

#### 4.4.1 Key 命名规范

| 规则项 | 取值 |
| --- | --- |
| 统一前缀 | 使用 `iw:` 前缀，后接业务域（如 `iw:model` / `iw:seen`） |
| 多级分隔符 | 用冒号 `:` 分层，禁止用下划线、点号 |
| 变量占位 | 用 `{}` 表示变量部分，如 `iw:seen:{site_id}` |
| 存储位置隔离 | `localStorage`（Web）/ `chrome.storage.local`（扩展）/ 本机文件（抓取器）分别存放，禁止跨端混用同一 Key |

#### 4.4.2 缓存策略与一致性

| 维度 | 在设计阶段需要明确的内容 |
| --- | --- |
| 读写策略 | Cache-Aside：本地缓存仅作加速与离线兜底，权威数据始终在云数据库 | 
| 一致性级别 | 最终一致；本地缓存与云库不要求强一致，刷新即覆盖 |
| 更新顺序 | 先写云库 → 成功后更新本地缓存；写云库失败则本地缓存不更新 |
| 失效防护 | 去重历史按站点独立文件，避免单文件过大；模型偏好为单值 Key，无击穿面 |
| 降级策略 | 本地缓存不可用（隐私模式）时退化为纯云端直查 |

#### 4.4.3 Key 清单

| Key 模式 | 类型 | TTL | 用途 | 写入位置 | 删除时机 |
| --- | --- | --- | --- | --- | --- |
| `iw:model:choice` | String | 永久 | 记录用户选择的模型偏好 | `ai.ts` 的 `MODEL_CHOICE_KEY` | 用户主动更换时覆盖 |
| `iw:seen:{site_id}` | JSON 文件 | 永久（滚动） | 抓取器跨轮次去重历史 | `crawler/run.mjs` | 手动 `--purge` 清理 |
| `iw:ext:clipboard` | String | 会话 | 扩展采集结果暂存 | `chrome.storage.local` | 导入后清除 |
| `iw:profile:default` | String | 永久 | 出厂目标条件模板骨架 | `constants.ts` 的 `PROFILE_TEMPLATE` | 用户覆盖后以库为准 |
| `iw:lock:{resource}` | String | 60s | 抓取器进程锁（`.profile/lockfile`） | `crawler/run.mjs` | 进程退出自动释放 |

**填写要求**：每条 Key 给出 TTL 数字；用途列明确"为什么用本地缓存而不直接查云端"（离线兜底 / 跨进程 / 加速）；写入位置写到函数级。

#### 4.5.1 迁移范围与数据源

| --- | --- | --- | --- | --- | --- |

#### 4.5.2 迁移方案选型

| 方案 | 适用场景 | 是否选用 | 说明 |
| --- | --- | --- | --- |
| 停机全量迁移 | 数据量小、可接受停机 | 否 | 无跨库迁移需求 |
| 存量 + 增量（双写） | 数据量大、不可停机 | 否 | 同一套库，无新旧双写 |
| 灰度切流 | 风险敏感 | 否 | 前端增量发布，无流量切换 |
| Schema 前向演进 | 同库加表 / 加列 | 是 | 采用 `db/migrations/` 顺序编号迁移，人工复核执行 |

**选型理由**：本系统数据始终在同一套云库，演进方式为"新增迁移文件 + 人工复核执行"（PostgREST 只接受单语句，SQL 由人复读后执行），不引入双写或 CDC。

#### 4.5.3 迁移分阶段计划

| 阶段 | 阶段名称 | 进入条件 | 退出条件 | 回滚预案 | Owner |
| --- | --- | --- | --- | --- | --- |
| T0 | 迁移评审 + 拆分脚本 | 评审通过 | `db/exec/singles/` 拆分脚本就绪 | 保留迁移文件原稿 | 平台底座组 |
| T1 | 001 jobs_public 建表 + 只读策略 | T0 完成 | 公共表可读且不可写 | DROP TABLE jobs_public | 平台底座组 |
| T2 | 002 resume_attachment 加列 | T1 稳定 | 简历附件四列就绪 | DROP COLUMN 四列 | 平台底座组 |
| T3 | 003 jobs_public_ingest 函数 | T2 完成 | SECURITY DEFINER 函数 + 配额生效 | DROP FUNCTION | 平台底座组 |
| T4 | 前端增量发布 + seed 灌库 | T3 稳定 | 线上 `app-version` 与期望一致 | 回滚前端构建 | 工作台组 |

#### 4.5.4 数据校验

| 校验类型 | 方式 | 阈值 |
| --- | --- | --- |
| 行数对比 | 迁移前后 COUNT(*) 抽样 | 偏差 = 0 |
| 内容对比 | 抽样 1‰ + 关键字段 checksum（dedupe_key） | 不一致率 ≤ 0.001% |
| 业务对账 | 岗位池 / 投递阶段计数对比 | 偏差 ≤ 0.01% |
| 实时差异告警 | seed 灌入幂等性检查（DELETE 后重建） | 重复灌入行数 = 0 |

#### 4.5.5 回滚预案

| 阶段 | 回滚动作 | RTO | 数据丢失风险 |
| --- | --- | --- | --- |
| T1 建表 | DROP TABLE jobs_public | ≤ 5 min | 0（公共库可重建） |
| T2 加列 | DROP COLUMN | ≤ 5 min | 0（列可空） |

## 6. 网络架构

> **本章定位**：本章只承载**对开发产生约束的网络结论**——开发要据此处理 HTTPS、限流位置、外部访问出口、服务发现与服务间通信。VPC / 子网 / CIDR 划分等运维施工细节见《部署设计》。

### 6.1 网络环境规划

| 网络环境 | 用途 | 说明 / 访问策略 |
| --- | --- | --- |
| 公网 | 用户浏览器 / 小程序访问云端站 | 仅 HTTPS；静态站与云服务入口统一走平台域名 |
| 平台托管网络 | 云数据库 / 认证 / LLM 通道 | 由平台托管，业务方无直接网络配置权 |
| 本机回环 | 本机网关 / 抓取器 | 网关仅监听 127.0.0.1，禁止对外暴露 |
| 用户本机浏览器 | 扩展与抓取器读取已渲染 DOM | 只读 activeTab；不发网络请求（扩展） |
| 外部出网 | OfferBiu / ATS / 微信 / LLM 厂商 / GitHub | 受 §6.2.2 出口白名单约束 |

### 6.2 流量入口与南北向流量

#### 6.2.1 入口流量链路

| 组件 | 作用 | 部署位置 |
| --- | --- | --- |
| DNS | 域名解析 | 公网 |
| 平台 HTTPS 入口 | TLS 终结 / 静态站与 API 分发 | 平台托管 |
| 静态托管（C-04） | 提供前端构建产物 | 平台托管 |
| 云服务 API | 数据库 / 认证 / LLM | 平台托管 |
| 本机网关（C-06） | 驱动抓取器 / 托管对话页 | 用户本机（127.0.0.1:5178） |

**入口决策（对开发的约束）**：

| 决策项 | 取值 | 对开发的约束 |
| --- | --- | --- |
| TLS 终结点 | 平台 HTTPS 入口 | 全链路强制 HTTPS；本机网关仅回环 HTTP |
| 限流位置 | 平台入口 + 业务自实现（配额三闸） | 业务侧配额须对接 §3.5.3 限流红线 |
| 鉴权位置 | 平台认证服务统一鉴权 | 与 §7.2.1 用户认证一致 |
| 真实客户端 IP 获取 | 平台注入头（`X-Forwarded-For`） | 业务获取客户端 IP 必须用本字段，不能直接用 socket 远端 IP |

#### 6.2.2 出口流量

| 决策项 | 取值 | 对开发的约束 |
| --- | --- | --- |
| 出口方式 | 平台 NAT 出口 + 本机直连 | 云端出网走平台；本机抓取器直连招聘平台 |
| 是否需要固定出口 IP | 否 | 无需对方白名单；OfferBiu 无鉴权无 SLA |
| 出口白名单 | OfferBiu 域名、ATS 域名、微信开放平台域名、LLM 厂商域名、GitHub 域名 | 业务对接 E-xx 必须使用白名单内域名；新增 E-xx 必须先登记 |
| 跨地域 / 跨云出口 | 公网 | 单一链路；延迟敏感操作（LLM）设 10s 超时 |

### 6.3 内部互联（东西向流量）

| 决策项 | 取值 | 对开发的约束 |
| --- | --- | --- |
| 服务发现 | 无（无自建服务）；本机进程用固定端口 127.0.0.1:5178 | 本机调用禁止硬编码外部 IP |
| 服务间通信协议 | 进程内调用 + 平台 HTTPS API | 与 §3.5.4 超时重试基线对齐 |
| 内部 mTLS | 不启用（无自建服务间通信） | — |
| 跨 VPC 互联 | 不适用（平台托管） | — |
| 跨账号互联 | 不适用 | — |
| 跨地域互联 | 不适用（单 Region） | — |
| 跨服务调用幂等性 | 必须遵循 §3.5.2 幂等键传递 | 跨调用必须在请求 Header 透传幂等键与 traceId（§8.3） |

**判定合格**：§6.1 / §6.2 / §6.3 决策项已锁定；TLS 终结点、限流位置、鉴权位置与 §3.5 / §7 一致；服务发现与服务间通信协议已锁定。

## 7. 安全设计

> **本章回答**：本系统在安全维度做了哪些选择、对应到哪些安全产品 / 能力域、关键机制如何落地。
> 更深细节（完整威胁模型 STRIDE、OWASP 防御对照）见《安全设计》，本章承载"机制选择 + 关键参数基线"。

### 7.1 架构安全全景

| 能力域 | 选用产品 / 机制 | 作用范围 | 是否启用 |
| --- | --- | --- | --- |
| 抗 DDoS | 平台托管入口防护 | 公网入口 | 是（由 WorkBuddy 平台统一保障） |
| WAF | 平台托管 WAF | Web 应用层 | 是（由平台统一保障） |
| 防火墙 / 安全组 | 平台托管网络隔离 | 平台托管网络 | 是（由平台统一保障） |
| 主机安全 | 无自建主机（BaaS） | — | 不适用（无自建服务器） |
| 容器安全 | 无自建容器（BaaS） | — | 不适用（无自建容器） |
| 数据安全审计 | 云服务审计日志 + RLS 策略审计 | 关键数据库 | 是 |
| 密钥管理（KMS） | 平台托管密钥 + 用户本机自持 Key | 敏感数据 / 自备 Key | 是 |
| 安全运营中心（SOC） | 平台托管安全监控 | 平台托管资源 | 是（由平台统一保障） |

**填写要求**：每个能力域均出现；不适用项填"不适用（无自建主机）"，无留空。

### 7.2 业务安全架构

#### 7.2.1 用户认证

| 维度 | 取值 |
| --- | --- |
| 账号体系 | 基于 WorkBuddy 云服务的平台账号体系（邮箱验证码 / 邮箱密码） |
| 登录方式 | Web 端邮箱验证码 / 邮箱密码；小程序端手机号短信 / 微信登录 |
| 多因素认证（MFA） | 不启用（MVP 单用户工具；完整版评估） |
| 密码强度 | 由平台认证服务强制（最小长度与复杂度由平台策略） |
| 登录失败锁定 | 单账号连续失败 5 次锁定 15 分钟 |
| Token 有效期 | 访问 Token 2h；刷新 Token 7d（平台托管） |
| 会话管理 | 多点登录允许；会话在云端；前端路由守卫校验会话有效性；注销即失效 |

**认证能力边界（与 D6 §6 一致）**：网页端仅邮箱验证码 / 密码；手机号短信与微信登录仅小程序端；不暴露某邮箱是否已注册；发码与验码分离，重试不重复发码，原样回传 `email` / `verificationId` / `isExistingUser`。

#### 7.2.2 数据安全

| 维度 | 取值 |
| --- | --- |
| 数据分级 | 三级：L1 公开（岗位广场） / L2 私有业务数据（岗位池 / 投递 / 面试 / Offer / 简历 / 知识 / 目标条件） / L3 敏感（邮箱、手机号等账号标识 / 用户会话 Token / 用户自备 Key） |
| 传输加密 | 云端强制 HTTPS（TLS）；本机网关仅回环 HTTP（数据不出机） |
| 存储加密 | 由平台托管存储加密（TDE）；本系统不额外做字段级加密 |
| 敏感字段清单 | 邮箱（账号标识） / 手机号（不落本项目库，仅平台认证托管） / 用户自备 Key（不落本项目库） / 会话 Token |
| 数据导出与共享 | 用户可导出 JSON 备份（不入仓库）；不向任何第三方共享 |

**敏感字段处理策略表**：

| 字段 | 分级 | 存储策略 | 展示策略（脱敏） | 导出策略 |
| --- | --- | --- | --- | --- |
| 邮箱 | L3 | 平台托管（账号标识） | 顶栏展示，列表内按需 | 可随本人备份导出；禁止整串打印日志，必要时掩码 |
| 手机号 | L3 | 不落本项目库（平台认证托管） | 仅小程序端按需；网页端不生成手机号路径 | 禁止导出 |
| 用户自备 Key | L3 | 不落本项目库（存用户设备） | 仅掩码展示 | 禁止导出 |
| 会话 Token | L3 | 平台托管（内存 / 安全存储） | 不展示 | 禁止导出 |
| 简历正文 | L2 | 私有表 RLS 存储 | 仅本人可见 | 可随备份导出 |
| 岗位 / 投递数据 | L2 | 私有表 RLS 存储 | 仅本人可见 | 可随备份导出 |

> **2026-09-29 修订**：邮箱 / 手机号由 L2 上调至 L3 敏感，修正原「敏感字段清单」与「敏感字段处理策略表」之间的分级不自洽。经用户裁决定点核准，与《安全设计》§3.1、《部署设计》口径统一为**三级**（L1 公开 / L2 私有业务数据 / L3 敏感）。

#### 7.2.3 密钥与凭证

| 维度 | 取值 |
| --- | --- |
| 存储方式 | 平台托管密钥（云端）+ 用户本机自持 Key（不发往本项目服务端） |
| 下发方式 | 平台会话 Token 由认证服务颁发；用户 Key 仅存用户设备 |
