# 本地岗位抓取器（`crawler/`）

跑在**你自己机器上**的批量岗位抓取：驱动你系统里已装的 Edge / Chrome，按站点表逐个打开招聘页，翻页读完列表，再逐个打开岗位详情页补全 JD，最后产出一份可以直接导入实习工作台的 JSON。

## 它是什么，不是什么

| | 本抓取器 | 浏览器扩展 | 服务端爬虫 |
| --- | --- | --- | --- |
| 跑在哪 | 你自己的机器 | 你的浏览器标签页 | 别人的服务器 |
| 翻页 | ✅ 自动 | ❌ 手动 | ✅ |
| 补全 JD | ✅ 逐个打开详情页 | ❌ | ✅ |
| 用谁的账号 | 你自己的 | 你自己的 | 通常也是你的，但你看不见 |
| 本项目有没有 | ✅ | ✅ | ❌ **没有，也不打算有** |

三点必须说清楚：

1. **它只读浏览器已经渲染出来的 DOM。** 在 DOM 模式下不调平台接口、不猜加密参数、不解密签名、不绕登录与验证码。你手动打开页面能看到什么，它就能拿到什么，不多一个字段。（另有一条 OfferBiu API 源，走**公开只读接口**、不登录不带 cookie —— 见下文「OfferBiu 校招库」一节。上面那句「不调平台接口」只覆盖 DOM 模式。）
2. **风控风险没有消失，只是变得可见。** 它用你的网络出口、你的登录态，所以请把它当「自动化的你自己」，而不是「一个可以随便跑的服务」：严格串行、每次请求之间强制等待且带随机抖动、单站点页数有上限、默认不并发。跑之前想清楚你在抓的是谁家的站点、对方的条款允不允许。
3. **提取算法不是这里写的。** 它注入 `extension/collector.js` 后调用同一个函数 —— 扩展手动点一次、抓取器自动跑一遍，读出来的字段必然一致。改提取逻辑请改那一个文件。

## 安装

```bash
cd crawler
npm install
```

只装一个 `playwright-core`（**不会下载几百 MB 的浏览器内核**）。它优先驱动系统已装的 Edge，其次 Chrome，都没有才提示你装：

```bash
npx playwright install chromium   # 仅在系统没有 Edge / Chrome 时需要
```

## 快速开始

```bash
npm run sites                                            # 看内置站点表（27 个）
npm run crawl -- --site tencent --keyword 前端              # 抓腾讯的「前端」岗
npm run selftest                                         # 自检：真浏览器跑本地夹具
```

产出在 `output/<站点>-<时间>.json` 与同名 `.txt`。导入：

> 打开工作台 →「岗位池」→「批量导入」→「**选择抓取结果文件**」→ 选那个 `.json` → 核对 → 入库

`.txt` 也能用（直接粘进导入框），但 JSON 多了来源标签，会走「直读、不过模型」那条路，不花额度。

## 命令参数

| 参数 | 说明 |
| --- | --- |
| `--site <id>` | 站点 id，可重复。用 `npm run sites` 看列表 |
| `--url <url>` | 任意招聘页地址，可重复。不用站点表也能抓 |
| `--keyword <kw>` | 岗位关键词，填进站点的查询参数，可重复（每个关键词是一条独立任务） |
| `--pages <n>` | 最多翻几页，默认 2 |
| `--limit <n>` | 单站点最多产出多少条，默认 60。**OfferBiu 源这一路按「上游记录数（≈公司数）」计，不等于岗位数**：一条记录挂了多个方向会拆成一条一岗，2026-09-27 实测 `--limit 20` 产出 241 个岗位。刻意不按岗位数截断——截断点要落在拆分之前才省得下请求，落在之后等于把已经拿回来的产出当场扔掉 |
| `--detail <n>` | 给前 n 条补全 JD，默认 20；`0` = 不补（快，但岗位没有 JD 正文，匹配分不准） |
| `--delay <ms>` | 请求之间的等待，默认 2600，会自动加最多 40% 随机抖动 |
| `--wait <ms>` | 页面渲染等待，覆盖站点自带的建议值（SPA 慢的时候加长） |
| `--mode <m>` | `all` \| `intern` \| `campus`，按标题筛，默认 all |
| `--include <词>` / `--exclude <词>` | 标题必须 / 不能包含，可重复 |
| `--company <名字>` | 页面里读不到公司名时用它补（用 `--url` 抓某家公司自己的站时很有用） |
| `--out <路径>` | 产出目录或 `.json` 路径，默认 `output/` |
| `--profile <路径>` | 浏览器档案目录，默认 `crawler/.profile`。**上一次抓取被强杀、`.profile/lockfile` 残留导致「没有可用的浏览器」时，用它换个目录绕开**（代价：已保存的登录态要重登） |
| `--resume` | 从上次中断的页继续 |
| `--purge` | 清掉去重历史，强制全量重出 |
| `--headed` | 显示浏览器窗口（调试） |
| `--dump` | 把渲染后的 HTML 存到 `output/dump/`（**抓不到东西时的第一招**） |
| `--quiet` | 只打印结果 |

### 例子

```bash
# 多个站点 + 多个关键词，不补 JD 先看量
npm run crawl -- --site tencent --site bytedance --keyword 前端 --keyword 后端 --pages 1 --detail 0

# 只要实习岗，标题必须含「Agent」
npm run crawl -- --site tencent --mode intern --include Agent

# 抓某家用 Moka 托管的校招页
npm run crawl -- --url https://app.mokahr.com/campus-recruitment/xxx/12345 --company 某某科技

# 上午没跑完，下午接着跑
npm run crawl -- --site tencent --pages 5 --resume
```

## 需要登录的站点

站点表里标了「需登录」的站点必须先登录。抓取器**不代填账号密码**，只让你自己登一次：

```bash
npm run login -- --site <id>          # 弹出一个独立窗口，你自己登录（含扫码/短信）
# 登录完回到终端按回车，档案保存到 crawler/.profile
npm run crawl -- --site <id> --keyword Python
```

> ⚠️ **BOSS 直聘不适用这一段**。它在默认内核下连登录页都过不去（页面无限重载、扫码扫不进去），
> 要走上面那一节的 `--login`（引擎由站点表自动选），而且档案是分开存的（`crawler/.profile-scrapling`）。
> 目前站点表里标「需登录」的只有 BOSS 这一个，所以这一段对其它站点是备着用的。

- 登录态存在 `crawler/.profile`（独立档案目录，**不影响你日常浏览器的书签、密码、登录状态**），已在 `.gitignore` 里。
- 脚本全程不读取、不打印、不上传任何 cookie 内容；只在开始前检查「有没有会话 cookie」并提示你一句。
- 想换账号或清掉登录态：直接删 `crawler/.profile`。

## BOSS 直聘：默认内核拿不到，引擎按站点表自动选

**先说这一步只有你能做**：BOSS 要登录，而登录**必须由你本人在弹出的窗口里扫码**。
抓取器不代填账号密码，也没有任何"自动登录"。所以下面所有命令之前，先跑一次：

```bash
node run.mjs --site boss --login          # 引擎由站点表自动选，不用手抄 --engine
# 会弹一个浏览器窗口 → 你扫码 → 终端每 5 秒检查一次，登上了自己存盘退出
# 最长等 15 分钟。窗口开着、终端没动静 = 它在等你，不是卡住
```

登录态存进 `crawler/.profile-scrapling`（已在 `.gitignore`，不会入库）。
**没有这个档案就抓不到东西** —— 列表页会给了页面但不给卡片。

### 为什么 BOSS 要单独一条路

BOSS 页面挂着 `browser-check-v2.js`（专门的浏览器检测 SDK）。**同一页面实测对比（2026-10-01）**：

| | 默认路径（系统 Edge/Chrome + Playwright） | `scrapling`（底层 patchright） |
|---|---|---|
| HTML 长度 | 8,496 字符（空壳） | 221,756 字符 |
| 岗位链接 | 0 | 17 |
| 观察 20 秒 | 页面一直重载 | URL 不变 |

换真 Edge 内核（`channel:'msedge'`）、抹 `navigator.webdriver` 等指纹、换 UA **三种都试过，全部无效**。
缺的不是网络也不是内核厂商，是**内核本身的反检测能力** —— patchright 有，所以这条路存在。

### 代价（装之前就得知道）

1. **多一门语言**：项目本来是纯 Node，这条路要 Python + scrapling。**默认路径一点都不依赖 Python**，
   没装的人照常爬其余 26 个站点；只有跑到**声明了引擎的站点**（现在只有 BOSS）才会去探测，探测不到就打印可照着做的安装命令（不抛 traceback），并且只判停那一站。
2. **匹配分明显差于其他 26 个站点**：这个引擎**只读列表页、不补详情页**，所以每条岗位的 `raw`（JD 正文）是空的，
   而「匹配度」依赖 JD 正文。**要准确匹配分请用浏览器扩展采集，或在网页上手动补 JD。**
   不补详情页是有意的：逐条打开详情页会明显加重风控（实测被拦两次、每次冷却约 90 秒）。
3. **只能串行、很慢、不能连着跑**：请求前固定等 5 秒、页间等 12 秒，且**必须 headed**（无头一律 0 张卡片）。
   连续快速请求会被打成 0 卡片，实测要**冷却约 90 秒**才恢复 —— 所以别把它挂成定时任务，也别连着重试。
   **建议单轮 `--pages ≤ 3`**（一页约 17 秒起）。给了更多页时引擎**照你给的跑**、只打一行提醒，
   不会替你砍：遇验证码会主动停，风险有上界，那就没有静默降值的正当理由。
4. **只有 BOSS 用它**：其它站点的 `engine` 字段是空的 ⇒ 自动走默认内核，完全不碰 Python。显式把 `--engine scrapling` 套到没声明的站点上会**判停那一站**（这个引擎没实现那个站点的解析），不会假装能跑，也不会悄悄改用别的内核。
5. **这个引擎不参与跨轮去重**：默认路径把「哪些岗位上一轮出过」记在 `output/.seen-<站点>__<关键词>.json`，`--purge` 能清；**scrapling 这条路不读也不写那份历史**（`writeCheckpoint` 只在 `crawlTarget` 里调用，引擎路径压根不经过它）。所以每次跑 BOSS 都会重出同一批岗位，重复导入靠工作台自身的去重键兜住 —— 但**别把它挂成定时任务**，否则每天重刷一遍相同岗位。

### 装什么

```bash
python -m venv <盘根>\iwb-engines-venv
<盘根>\iwb-engines-venv\Scripts\python.exe -m pip install -i https://mirrors.aliyun.com/pypi/simple/ "scrapling[all]"
```

**venv 故意不放仓库内**（放 `crawler\engines\.venv` 也支持，但那样防护只剩一行 `.gitignore`，
一次 `git add -A` 失手就是几百 MB 进 git 历史、且历史里删不掉）。放仓库外是**结构上不可能**误提交。
放别处就用 `set IWB_SCRAPLING_PYTHON=<那个>\Scripts\python.exe` 指过去。

探测顺序：`IWB_SCRAPLING_PYTHON` → 与仓库盘根同级的 `iwb-engines-venv` → `crawler/engines/.venv` → PATH 上能 `import scrapling` 的解释器。
**浏览器内核不用重下**：patchright 1.63 用的 `chromium-1243` 与 Playwright 共用 `%LOCALAPPDATA%\ms-playwright` 缓存（实测 704 MB 已在）。
`real_chrome=True` 那条路要另装 Google Chrome，本机没有就会报 `Chromium distribution 'chrome' is not found`，**用默认即可**。

### 用法

**不用手写 `--engine`**：`sites.mjs` 里 BOSS 那条已经声明了 `engine: 'scrapling'`，抓取器按声明路由。

```bash
node run.mjs --site boss --keyword "AI Agent" --pages 1
node run.mjs --site boss --keyword "AI Agent" --decode-salary   # 见下面「薪资」
node run.mjs --site boss --login                                # 第一次要本人扫码
```

`--engine <名字>` 还在，但它是**覆盖开关**（调试时故意指定内核），不是常规入口。
它的行为表见下面「引擎怎么选」一节。

产出与默认路径**同一个文件形态**（`output/boss-<关键词>-<时间>.json` + `.txt`），
批量导入读法完全一样。格式由 Node 侧同一个 `makePayload` 拼，Python 只吐裸 jobs ——
所以「导入读得了」不靠两边手抄字段名。

### 引擎怎么选（行为表）

```
不带 --engine 时：
  · 站点表没声明 engine 的站点 → 走默认内核（Edge/Chrome + Playwright），完全不依赖 Python
  · 站点表声明了 engine 的站点 → 按声明路由；该引擎环境缺失时【只判停那一站】，
                                 其余站点照跑，【整轮退出码非零】
带 --engine <名字> 时：
  · 用它，覆盖站点表（调试用，结果自负）
  · 值不认识 ⇒ 硬失败退出，绝不悄悄回落默认内核
```

**为什么"没声明就不路由"是死规矩**：一旦允许「我记得这站以前要用引擎」这种隐式判断，
声明字段就退化成另一份要靠人记得的东西 —— 而这张表存在的目的正是让它是**唯一事实源**。
这条行为由 `lib/routing.mjs` 实现，并被 `__tests__/engineRouting.test.mjs` 钉住（12 条断言）。

**混合一轮是可以的**：`node run.mjs --site tencent --site boss --keyword 实习` ——
默认内核批先跑完，再跑引擎批，汇总里**每个目标都标注所用引擎**，
判停的站会单列「哪一站、原因、其余几站成败几何」。
部分成功不把退出码洗成 0 —— 「部分成功」最容易被读成「全成功」，那是我们最不想造出来的形状。

### 已知可改进（探测能力已有，还没用上）

`resolvePython()` 已经会判断「哪个解释器装了 scrapling」——它现在只用于两件事：选一个能用的解释器，
以及把探到的路径写进判停提示。**它还没有用于：自动复用一个你本机别处已装好 scrapling 的环境。**

也就是说 `crawler/engines/.venv` 没建时，理论上可以直接捡起 `D:\iwb-engines-venv` 之外任何装了
scrapling 的解释器来用，而不必先提示用户去装。**本轮不做，两个理由：**

1. **可复现性**：换解释器等于换一套依赖版本。今天跑通用的是 A，明天探到 B 就悄悄切过去，
   出了问题时"我这台机器装了什么"没人答得准。显式声明（`IWB_SCRAPLING_PYTHON` 或项目 venv）
   把选择权留给人，代价只是多打一次安装提示。
2. **超出本轮范围**：(A) 要解决的是"路由由声明决定"，不是"环境自动发现"。混在一起做，
   两件事的验收都会变模糊。

**要改的话，判据先立好**：自动复用时必须在日志里写明"复用了 X（用户未指定）"，
并且**不允许跨大版本静默切换**——否则这就是又一个不可见的自动决策。

### 薪资：默认**不解**，要显式加 `--decode-salary`

BOSS 列表页的薪资数字被换成 Unicode 私有区码位（本项目对这件事的政策见下面「列表页被字体反爬时」一节：
**默认不解这层映射**）。所以：

- **不加 `--decode-salary`（默认）**：带混淆的薪资**一律丢弃为空串**。原始码位绝不进产出 ——
  那会在岗位池里渲染成一排空框。实测一份 15 条的产出：15 条全空、0 个码位泄漏。
- **加了 `--decode-salary`**：用**内置的连续映射表**（`U+E031 + n = 数字 n`，2026-10 实测得出）把码位解成数字。
  **默认不做每轮现场对账** —— 见下面「为什么对账是可选的」。
  真跑实测：一份 15 条的产出 15/15 有值（`270-450元/天`、`200-250元/天`、`12-24K·14薪`），
  且**只混淆 `salary` 这一个字段**（60 条真实产出里 title / company / city 的私有区码位数全是 0）。
- **认不出的码位**（不在私有区连续段内）：该条薪资整条置 `null`，日志点名「第几条、哪些码位」，
  Node 侧汇总成「N 条薪资未能解码」。**绝不留一个看着合理的字符串。**

> ⚠️ **时间点说明**：`--decode-salary` 是 2026-10-02 引入的默认行为变更。
> 在此之前跑出的 BOSS 产出（含 10-01 导入工作台那 15 条）薪资是**解过的**。
> 从现在起，**新跑的不加这个开关就没有薪资**。

### 为什么现场对账是「可选诊断」，不是每轮必跑

引擎里另有一条**现场量映射**的路径（canvas 用页面自己生效的字体画 0~9 与各码位、取像素海明距离，
距离 >3 判不可信、次选领先不足 2 判不可分辨）。它一度被设成"每轮跑一次并与内置表对账"，
**2026-10-02 真跑三次后降级成可选**，实测数据是：

    现场量出 1 个可信码位（共量 7~9 个）
    U+E031→0 海明距离 17 > 3，不信      U+E033→2 距离 10 > 3，不信      …共 6 条

**9 个码位只认下 1 个、6 个误拒。** 一条每轮喊 6 次的防线等于没有防线 ——
**告警一多就会被忽略，那是另一种假成功。** 所以：

```bash
node run.mjs --site boss --keyword "AI Agent" --decode-salary --check-salary-font
# 只有 --check-salary-font 才现场量映射，并把每个码位的海明距离、次选领先、是否可信整表输出
```

**当前薪资值的可信度依据是两条间接证据，不是当次页面证实**：
① 2026-10-01 那份现场量出的 8 键表（`salary_font_map.json`）在 0–7 上与连续映射**逐位吻合**；
② 解出来的值全是整十/百（`270-450元/天`、`200-250元/天`）—— 映射若错会出 `740-290` 这种不可能值。
⚠️ 另需知道：`U+E039`/`U+E03A`（数字 8、9）**在真实数据里确实被用到**，但那份现场表只覆盖 0–7，
所以 8、9 属于**外推**。（用连续映射本身去数码位**不能**证明它们的映射值正确 —— 那是循环论证，
只能证明"这两个码位被用到"。要证实只能靠 `--check-salary-font` 落在含 8/9 的页面上。）

**已知未解（探针为什么大面积误拒）** —— 两个候选根因，各自都值一次真打 BOSS + 90 秒冷却，
**因为现在它只是可选诊断，收益不成立，先挂在这里**：
1. `getComputedStyle(els[0]).fontFamily` 取的是**外层** `.job-salary`，真正生效的混淆字体可能挂在**内层节点**；
2. canvas 画私有区码位时走 `.notdef` 方框（字体没进 canvas 的 font set），那么数字与码位的像素本来就不可比。

**已经被证伪的假设，留给下一个想到它的人**：
> ~~"是 webfont 还没加载 → 画的是回退字形 → 距离虚高"~~
> 已按此把探针改成 `async` + `await document.fonts.ready` 再量，**重跑仍然 1 认下、6 误拒。假设被推翻。**

### 为什么 `--engine` 的失败规则和其它参数相反

`parseArgs` 对**未知参数**的行为是「不报错、记进 `unknown`、让调用方看到」——
这是有意的向后兼容设计，`__tests__/normalize.test.mjs:57` 把这条写成了契约。

**但引擎相关的失败走的是相反的规则：值不认识 ⇒ 非零退出 + 明确报错，绝不回落默认内核；
环境缺失 ⇒ 只判停声明了该引擎的那些目标，其余站点照跑，整轮退出码仍然非零。**

因为对引擎来说，"忽略并继续"的后果是**假成功**：它会用默认内核去爬一个已知拿不到卡片的站点，
拿到 0 条，而唯一的线索是一行会被几十行输出淹掉的日志。**假成功比失败危险**，所以这一条不给兜底。

**这条规则为什么值得单独写**：它同时管住两个方向的错 ——
既不许「不认识就悄悄走默认」，也不许「一站环境缺失就整轮失败」或「跳过去当没这回事」。
三条都被 `__tests__/engineRouting.test.mjs` 钉着。

### 列表页被字体反爬时，靠详情页把那几条字段救回来

有的站（实习僧是最典型的一个）会把列表页上的数字和部分汉字换成**自定义字体 + Unicode 私有区码位**：
屏幕上看着是「250-400/天」，DOM 里拿到的是一串 `U+E600` 这类空框。**本项目不去解这层映射** ——
那要逆向对方专门用来拦抓取的字体文件，属于破别人的保护措施，不在这条线内。

能做的是**换一份数据源**：详情页通常没做这层混淆。于是 `mergeDetail` 合成一条时先挑「干净的一侧」——
带私有区字符的值一律算不可信，两边都脏才保留列表那份（不做「谁长取谁」那种没根据的猜测）。
这条规则是补上来的：之前是「列表优先」，等于让乱码压掉详情页的干净数据，
产出看着抓到了、导进岗位池就是一堆空框。跑出来的实况（2026-09-27，同一批 4 条）：
公司从「互联网/游戏/软件/…以上」这种标签行变成 `百度 / 跨赴科技 / 原力金智 / 网易有道`，
岗位从「六个空框 + 策略实习」变成 `Agent策略实习生`，详情正文 988~1356 字且不含私有区字符。

**这条规则（`normalize.mjs:41` 的 `OBFUSCATED`）管的范围是默认路径**：`mergeDetail` 合成列表/详情两份数据时，
把带私有区码位的那一侧判为不可信。**它不是全局禁令。** BOSS 走 `--decode-salary` 时，
码位在**引擎侧就已经解成数字**了，进 `jobs` 的是解出来的 `250-400元/天`，压根不含码位 ——
所以**不经过 `OBFUSCATED` 判定不是绕过检查，是换了数据来源**。默认（不加那个开关）仍然是丢空，见上一节。

```json
{

  "version": 1,
  "channel": "官网投递",
  "site_id": "tencent",
  "collected_at": "2026-09-23T09:18:00.000Z",
  "page": { "url": "https://join.qq.com/post.html", "title": "腾讯招聘", "site": "join.qq.com" },
  "count": 10,
  "jobs": [
    { "company": "腾讯", "title": "AI全栈工程师", "city": "深圳", "salary": "", "url": "", "deadline": "", "raw": "岗位原文…" }
  ],
  "text": "# 采集自 …\n\n公司：腾讯\n岗位：…"

```

字段名与浏览器扩展的采集结果**逐字一致**（`src/lib/import.ts#parseCollectorJson` 只认这一套）。多出来的 `channel` 是来源标签，工作台优先用它，没有才按域名猜。`deadline` 是结构化源才能给到的投递截止日（`yyyy-mm-dd`），DOM 抓取一般是空串 —— 它直接喂给概览页的临近截止待办，所以能拿到就别丢。`output/.seen-<站点>.json` 是跨轮次去重历史（避免每天重复产出同一批岗位），`--purge` 清掉它。

## OfferBiu 校招库（API 源，不需要浏览器）

`sites.mjs` 里的站点全是 **DOM 翻页**型（进列表页、点下一页、认卡片结构）。OfferBiu 不一样：
它是 **JSON API**，一次请求就能拿到「公司 + 岗位 + 地点 + 投递截止日 + 官方公告链接 + 投递入口 + 公司性质 + 行业分类」，
字段密度是 DOM 抓取拿不到的。实测 2027 届秋招库内 **5860 条 / 293 页**。

```bash
# 取 300 条落到本地（推荐：先落盘，重复用不要反复打对方接口）
node crawler/sources/offerbiu.mjs --season 2027 --limit 300 --out crawler/output/offerbiu-2027.json

# 只按行业大类取（多值用逗号分隔）
node crawler/sources/offerbiu.mjs --season 2027 --groups internet-tech,consumer-retail --limit 100

# 先小量试一条链路
node crawler/sources/offerbiu.mjs --season 2027 --limit 20
```

产出走的就是上面那套采集器 JSON 契约（`channel` 固定为「岗位广场」，`site_id` 为 `offerbiu`），
所以工作台「岗位池 → 批量导入」选中它即可，**不消耗模型额度**。

**合规边界（这类功能最容易越界，所以写死在代码注释里）**：只读公开接口、不登录不带 cookie、
请求间隔默认 1.2 秒且不做并发、只取公开字段、产出物标注来源、鼓励落盘缓存。
对方 `robots.txt` 当前为空——**空 robots 不等于许可**，所以按以上更严标准自我约束；
若对方将来明确禁止，这条源应当直接删掉，而不是改换姿势继续抓。

## 抓不到东西怎么办

按顺序试，别跳步：

1. **`--dump`** —— 存下渲染后的 HTML，直接看页面到底长什么样。大多数「抓不到」都能在这一步看清原因。
2. **`--wait 10000`** —— SPA 渲染比站点建议值慢。
3. **`--headed`** —— 亲眼看一遍：是不是要登录？是不是要滚动才加载？是不是弹了 Cookie 弹窗？
4. **`--pages 1 --detail 0`** —— 先确认列表能读，再谈翻页和补 JD。
5. **`npm run login -- --site <id>`** —— 需要登录的站点。
6. **报「没有可用的浏览器」时，先看 `.profile/lockfile` 在不在** —— 在，说明上次抓取被强杀留下了锁（不是浏览器没装）：关掉抓取器打开的窗口后删掉它，或 `--profile .profile2` 换个目录绕开。

### 两个真实案例

**案例一：腾讯招聘只读到 1 条（「卡片必须含链接」是错的）**

开发时跑腾讯招聘，第一次只读到 **1 条**。`--dump` 看 HTML 才发现：腾讯的岗位卡是 `<li class="post_box">`，里面**一个 `<a href>` 都没有**（纯 div + 点击事件），而当时的卡片检测硬性要求「卡片内含链接」，于是整页退化成「1 个岗位」。去掉这个硬性要求后变成 **10 条，标题与城市 10/10 全对**。

这条经验固化成两件事：`--dump` 现在是排查标配；`crawler/__tests__/contract.test.mjs` 与 `selftest.mjs` 会钉住「没有链接的卡片也要能读」。

**案例二：美团校招把 JD 正文当成了岗位名（数量不能单独当主键）**

接入美团时，抓到的 4 条「岗位」标题是：

```
1. 负责各类后台服务和业务系统的需求分析、系统设计、开发实现；
1. 参与业务规划、策略制定、经营分析，为复杂的商业问题设计解决方案；
```

这些是**岗位职责的编号段落**，不是岗位名。真标题是「AI全栈工程师」「AI后端开发工程师」。

根因：美团页面里 `div.position_list_item`（真卡片）有 10 个，但每张卡里的 `div.desc.hidden-ellipsis`（JD 段落）有 20 个。卡片检测的排序是 `数量 × 1000`，**碎片靠数量优势直接压过真卡片**。

修法不是调权重（碎片永远更多，软乘数压不住），而是**加硬门槛**：真卡片的父容器是「列表壳」（文本 ≈ 全部卡片拼起来），碎片的父容器**就是卡片本身**。于是：

- 门槛一：父容器文本 ≥ 单张卡的 **2 倍**，否则淘汰。
- 门槛二：若本组的父链上存在**文本完全相同**的别组元素，说明它只是卡片内壳，淘汰。

改完后：**10 条，公司/标题/城市全对。**

**案例三：公司名变成「更新于2026/08/17」（单公司招聘板要覆盖而不是填空）**

同一次接入里，标题对了但公司名变成了卡片正文行。原因是 `run.mjs` 的补全逻辑写成了「**只在 `company` 为空时**才用站点表补」，而卡片内启发式已经**猜出了一个错误的值** —— 非空，于是站点表不生效。

对单公司招聘板（腾讯/美团/拼多多…各家的官网），页面里根本没有公司字段，启发式只能在卡片里挑一个「像公司名」的短行，必然误判。既然 `BOARD_COMPANY` 已经确定知道这家招聘板属于谁，那就是**事实**，不该被猜测覆盖。改成「**覆盖**」后正常。

`crawler/__tests__/contract.test.mjs` 现在会检查：所有单公司招聘板都必须在 `BOARD_COMPANY` 里有名字，且多公司平台**不能**有名字。

## 已知限制

- **详情页要点击才展开的站点读不到 JD。** 有些官方校招站把岗位职责放在抽屉/弹窗里，列表页只有摘要。抓取器目前不会模拟点击展开 —— 这类岗位会以「有标题、没有 JD 正文」的状态进池（工作台会标提醒，建议手动补）。
- **列表页里没有链接的卡片，`url` 是空的。** 不会拿列表页地址冒充岗位链接（那会让补 JD 把列表页抓成岗位），所以这些岗位只能靠标题与城市，要投递时得自己回站点找。
- **虚拟列表只读到当前窗口。** 靠滚动触发的列表，滚动到底 3 次仍不见增长就停。
- **`salary` 常常为空。** 官方校招页普遍不写薪资，不是读漏了。
- **站点表可能过期。** 见上面的验证状态说明。
- **不做定时任务。** 想每天跑，用系统计划任务调用 `npm run crawl`，但请自己评估目标站点的条款与频率。

## 自检

```bash
npm run selftest
```

用真浏览器（本机 Edge / Chrome）+ `extension/fixtures` 的两个本地夹具，断言 40 项：列表页 6 条的全字段、详情页的公司/城市/薪资、详情页兜底分支、正文没把导航收进来。**不碰任何真实招聘站点**，所以它不受站点改版与风控影响，是可以长期留着跑的那类测试。

需要浏览器的那部分不进 vitest（CI 上不一定有 Edge）；抓取器的纯逻辑（标题筛选、去重、断点、参数解析）在 `__tests__/` 下用 vitest 跑，`npm test` 就会带上。
