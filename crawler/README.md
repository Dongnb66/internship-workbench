# 本地岗位抓取器（`crawler/`）

跑在**你自己机器上**的批量岗位抓取：驱动你系统里已装的 Edge / Chrome，按站点表逐个打开招聘页，翻页读完列表，再逐个打开岗位详情页补全 JD，最后产出一份可以直接导入实习工作台的 JSON。

## 它是什么，不是什么

| | 本抓取器 | 浏览器扩展 | 服务端爬虫 |
| --- | --- | --- | --- |
| 跑在哪 | 你自己的机器 | 你的浏览器标签页 | 别人的服务器 |
| 翻页 | ✅ 自动 | ❌ 手动 | ✅ |
| 补全 JD | ✅ 逐个打开详情页 | ❌ | ✅ |
| 用谁的账号 | 你自己的 | 你自己的 | 通常也是你的，但你看不见 |
| 本项目有没有 | ✅ | ✅ | ❌ **没有，也不打算有** |

三点必须说清楚：

1. **它只读浏览器已经渲染出来的 DOM。** 不调平台接口、不猜加密参数、不解密签名、不绕登录与验证码。你手动打开页面能看到什么，它就能拿到什么，不多一个字段。
2. **风控风险没有消失，只是变得可见。** 它用你的网络出口、你的登录态，所以请把它当「自动化的你自己」，而不是「一个可以随便跑的服务」：严格串行、每次请求之间强制等待且带随机抖动、单站点页数有上限、默认不并发。跑之前想清楚你在抓的是谁家的站点、对方的条款允不允许。
3. **提取算法不是这里写的。** 它注入 `extension/collector.js` 后调用同一个函数 —— 扩展手动点一次、抓取器自动跑一遍，读出来的字段必然一致。改提取逻辑请改那一个文件。

## 安装

```bash
cd crawler
npm install
```

只装一个 `playwright-core`（**不会下载几百 MB 的浏览器内核**）。它优先驱动系统已装的 Edge，其次 Chrome，都没有才提示你装：

```bash
npx playwright install chromium   # 仅在系统没有 Edge / Chrome 时需要
```

## 快速开始

```bash
npm run sites                                            # 看内置站点表（27 个）
npm run crawl -- --site tencent --keyword 前端              # 抓腾讯的「前端」岗
npm run selftest                                         # 自检：真浏览器跑本地夹具
```

产出在 `output/<站点>-<时间>.json` 与同名 `.txt`。导入：

> 打开工作台 →「岗位池」→「批量导入」→「**选择抓取结果文件**」→ 选那个 `.json` → 核对 → 入库

`.txt` 也能用（直接粘进导入框），但 JSON 多了来源标签，会走「直读、不过模型」那条路，不花额度。

## 命令参数

| 参数 | 说明 |
| --- | --- |
| `--site <id>` | 站点 id，可重复。用 `npm run sites` 看列表 |
| `--url <url>` | 任意招聘页地址，可重复。不用站点表也能抓 |
| `--keyword <kw>` | 岗位关键词，填进站点的查询参数，可重复（每个关键词是一条独立任务） |
| `--pages <n>` | 最多翻几页，默认 2 |
| `--limit <n>` | 单站点最多产出多少条，默认 60 |
| `--detail <n>` | 给前 n 条补全 JD，默认 20；`0` = 不补（快，但岗位没有 JD 正文，匹配分不准） |
| `--delay <ms>` | 请求之间的等待，默认 2600，会自动加最多 40% 随机抖动 |
| `--wait <ms>` | 页面渲染等待，覆盖站点自带的建议值（SPA 慢的时候加长） |
| `--mode <m>` | `all` \| `intern` \| `campus`，按标题筛，默认 all |
| `--include <词>` / `--exclude <词>` | 标题必须 / 不能包含，可重复 |
| `--company <名字>` | 页面里读不到公司名时用它补（用 `--url` 抓某家公司自己的站时很有用） |
| `--out <路径>` | 产出目录或 `.json` 路径，默认 `output/` |
| `--profile <路径>` | 浏览器档案目录，默认 `crawler/.profile`。**上一次抓取被强杀、`.profile/lockfile` 残留导致「没有可用的浏览器」时，用它换个目录绕开**（代价：已保存的登录态要重登） |
| `--resume` | 从上次中断的页继续 |
| `--purge` | 清掉去重历史，强制全量重出 |
| `--headed` | 显示浏览器窗口（调试） |
| `--dump` | 把渲染后的 HTML 存到 `output/dump/`（**抓不到东西时的第一招**） |
| `--quiet` | 只打印结果 |

### 例子

```bash
# 多个站点 + 多个关键词，不补 JD 先看量
npm run crawl -- --site tencent --site bytedance --keyword 前端 --keyword 后端 --pages 1 --detail 0

# 只要实习岗，标题必须含「Agent」
npm run crawl -- --site tencent --mode intern --include Agent

# 抓某家用 Moka 托管的校招页
npm run crawl -- --url https://app.mokahr.com/campus-recruitment/xxx/12345 --company 某某科技

# 上午没跑完，下午接着跑
npm run crawl -- --site tencent --pages 5 --resume
```

## 需要登录的站点

BOSS 直聘这类站点必须先登录。抓取器**不代填账号密码**，只让你自己登一次：

```bash
npm run login -- --site boss          # 弹出一个独立窗口，你自己登录（含扫码/短信）
# 登录完回到终端按回车，档案保存到 crawler/.profile
npm run crawl -- --site boss --keyword Python
```

- 登录态存在 `crawler/.profile`（独立档案目录，**不影响你日常浏览器的书签、密码、登录状态**），已在 `.gitignore` 里。
- 脚本全程不读取、不打印、不上传任何 cookie 内容；只在开始前检查「有没有会话 cookie」并提示你一句。
- 想换账号或清掉登录态：直接删 `crawler/.profile`。

## 站点表（验证状态）

`npm run sites` 可看实时列表。状态的含义：

- `live` —— 在开发机上真跑通过，**且逐条核对过抓到的确实是岗位名**，当时这些 URL 与翻页方式有效
- `offline` —— 真跑过但**当前不可用**，原因写在 `notes` 里（两种：岗位列表要再点一次站内导航才出现；或者数量看着好看，但抓到的根本不是岗位）
- `未验证` —— 没试过，第一次跑可能失败

标注写在 `sites.mjs` 的 **`notes` 字段**里（不是代码注释）—— 注释代码读不到，复制站点对象时还会丢。`crawler/__tests__/contract.test.mjs` 会检查：标了 `live` 的必须有实跑结论、标了 `offline` 的必须说清原因、**从 `live` 降级到 `offline` 的必须写明「抓到了什么但不是岗位」**，防止有人顺手把 `offline` 改成 `live` 让自己好交代，或者反过来把降级理由一起删掉、让下一个人再试一遍同样的 URL。

> **⚠️ 只看条数会被骗。** 真跑时踩到三个「数量好看但不是岗位」的坑，三个都曾被我当成 `live`：

## 产出格式

```json
{
  "source": "实习工作台抓取器",
  "version": 1,
  "channel": "官网投递",
  "site_id": "tencent",
  "collected_at": "2026-09-23T09:18:00.000Z",
  "page": { "url": "https://join.qq.com/post.html", "title": "腾讯招聘", "site": "join.qq.com" },
  "count": 10,
  "jobs": [
    { "company": "腾讯", "title": "AI全栈工程师", "city": "深圳", "salary": "", "url": "", "deadline": "", "raw": "岗位原文…" }
  ],
  "text": "# 采集自 …\n\n公司：腾讯\n岗位：…"
}
```

字段名与浏览器扩展的采集结果**逐字一致**（`src/lib/import.ts#parseCollectorJson` 只认这一套）。多出来的 `channel` 是来源标签，工作台优先用它，没有才按域名猜。`deadline` 是结构化源才能给到的投递截止日（`yyyy-mm-dd`），DOM 抓取一般是空串 —— 它直接喂给概览页的临近截止待办，所以能拿到就别丢。`output/.seen-<站点>.json` 是跨轮次去重历史（避免每天重复产出同一批岗位），`--purge` 清掉它。

## OfferBiu 校招库（API 源，不需要浏览器）

`sites.mjs` 里的站点全是 **DOM 翻页**型（进列表页、点下一页、认卡片结构）。OfferBiu 不一样：
它是 **JSON API**，一次请求就能拿到「公司 + 岗位 + 地点 + 投递截止日 + 官方公告链接 + 投递入口 + 公司性质 + 行业分类」，
字段密度是 DOM 抓取拿不到的。实测 2027 届秋招库内 **5860 条 / 293 页**。

```bash
# 取 300 条落到本地（推荐：先落盘，重复用不要反复打对方接口）
node crawler/sources/offerbiu.mjs --season 2027 --limit 300 --out crawler/output/offerbiu-2027.json

# 只按行业大类取（多值用逗号分隔）
node crawler/sources/offerbiu.mjs --season 2027 --groups internet-tech,consumer-retail --limit 100

# 先小量试一条链路
node crawler/sources/offerbiu.mjs --season 2027 --limit 20
```

产出走的就是上面那套采集器 JSON 契约（`channel` 固定为「岗位广场」，`site_id` 为 `offerbiu`），
所以工作台「岗位池 → 批量导入」选中它即可，**不消耗模型额度**。

**合规边界（这类功能最容易越界，所以写死在代码注释里）**：只读公开接口、不登录不带 cookie、
请求间隔默认 1.2 秒且不做并发、只取公开字段、产出物标注来源、鼓励落盘缓存。
对方 `robots.txt` 当前为空——**空 robots 不等于许可**，所以按以上更严标准自我约束；
若对方将来明确禁止，这条源应当直接删掉，而不是改换姿势继续抓。

## 抓不到东西怎么办

按顺序试，别跳步：

1. **`--dump`** —— 存下渲染后的 HTML，直接看页面到底长什么样。大多数「抓不到」都能在这一步看清原因。
2. **`--wait 10000`** —— SPA 渲染比站点建议值慢。
3. **`--headed`** —— 亲眼看一遍：是不是要登录？是不是要滚动才加载？是不是弹了 Cookie 弹窗？
4. **`--pages 1 --detail 0`** —— 先确认列表能读，再谈翻页和补 JD。
5. **`npm run login -- --site <id>`** —— 需要登录的站点。
6. **报「没有可用的浏览器」时，先看 `.profile/lockfile` 在不在** —— 在，说明上次抓取被强杀留下了锁（不是浏览器没装）：关掉抓取器打开的窗口后删掉它，或 `--profile .profile2` 换个目录绕开。

### 两个真实案例

**案例一：腾讯招聘只读到 1 条（「卡片必须含链接」是错的）**

开发时跑腾讯招聘，第一次只读到 **1 条**。`--dump` 看 HTML 才发现：腾讯的岗位卡是 `<li class="post_box">`，里面**一个 `<a href>` 都没有**（纯 div + 点击事件），而当时的卡片检测硬性要求「卡片内含链接」，于是整页退化成「1 个岗位」。去掉这个硬性要求后变成 **10 条，标题与城市 10/10 全对**。

这条经验固化成两件事：`--dump` 现在是排查标配；`crawler/__tests__/contract.test.mjs` 与 `selftest.mjs` 会钉住「没有链接的卡片也要能读」。

**案例二：美团校招把 JD 正文当成了岗位名（数量不能单独当主键）**

接入美团时，抓到的 4 条「岗位」标题是：

```
1. 负责各类后台服务和业务系统的需求分析、系统设计、开发实现；
1. 参与业务规划、策略制定、经营分析，为复杂的商业问题设计解决方案；
```

这些是**岗位职责的编号段落**，不是岗位名。真标题是「AI全栈工程师」「AI后端开发工程师」。

根因：美团页面里 `div.position_list_item`（真卡片）有 10 个，但每张卡里的 `div.desc.hidden-ellipsis`（JD 段落）有 20 个。卡片检测的排序是 `数量 × 1000`，**碎片靠数量优势直接压过真卡片**。

修法不是调权重（碎片永远更多，软乘数压不住），而是**加硬门槛**：真卡片的父容器是「列表壳」（文本 ≈ 全部卡片拼起来），碎片的父容器**就是卡片本身**。于是：

- 门槛一：父容器文本 ≥ 单张卡的 **2 倍**，否则淘汰。
- 门槛二：若本组的父链上存在**文本完全相同**的别组元素，说明它只是卡片内壳，淘汰。

改完后：**10 条，公司/标题/城市全对。**

**案例三：公司名变成「更新于2026/08/17」（单公司招聘板要覆盖而不是填空）**

同一次接入里，标题对了但公司名变成了卡片正文行。原因是 `run.mjs` 的补全逻辑写成了「**只在 `company` 为空时**才用站点表补」，而卡片内启发式已经**猜出了一个错误的值** —— 非空，于是站点表不生效。

对单公司招聘板（腾讯/美团/拼多多…各家的官网），页面里根本没有公司字段，启发式只能在卡片里挑一个「像公司名」的短行，必然误判。既然 `BOARD_COMPANY` 已经确定知道这家招聘板属于谁，那就是**事实**，不该被猜测覆盖。改成「**覆盖**」后正常。

`crawler/__tests__/contract.test.mjs` 现在会检查：所有单公司招聘板都必须在 `BOARD_COMPANY` 里有名字，且多公司平台**不能**有名字。

## 已知限制

- **详情页要点击才展开的站点读不到 JD。** 有些官方校招站把岗位职责放在抽屉/弹窗里，列表页只有摘要。抓取器目前不会模拟点击展开 —— 这类岗位会以「有标题、没有 JD 正文」的状态进池（工作台会标提醒，建议手动补）。
- **列表页里没有链接的卡片，`url` 是空的。** 不会拿列表页地址冒充岗位链接（那会让补 JD 把列表页抓成岗位），所以这些岗位只能靠标题与城市，要投递时得自己回站点找。
- **虚拟列表只读到当前窗口。** 靠滚动触发的列表，滚动到底 3 次仍不见增长就停。
- **`salary` 常常为空。** 官方校招页普遍不写薪资，不是读漏了。
- **站点表可能过期。** 见上面的验证状态说明。
- **不做定时任务。** 想每天跑，用系统计划任务调用 `npm run crawl`，但请自己评估目标站点的条款与频率。

## 自检

```bash
npm run selftest
```

用真浏览器（本机 Edge / Chrome）+ `extension/__fixtures__` 的两个本地夹具，断言 40 项：列表页 6 条的全字段、详情页的公司/城市/薪资、详情页兜底分支、正文没把导航收进来。**不碰任何真实招聘站点**，所以它不受站点改版与风控影响，是可以长期留着跑的那类测试。

需要浏览器的那部分不进 vitest（CI 上不一定有 Edge）；抓取器的纯逻辑（标题筛选、去重、断点、参数解析）在 `__tests__/` 下用 vitest 跑，`npm test` 就会带上。
