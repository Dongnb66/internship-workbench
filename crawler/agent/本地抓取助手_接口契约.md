# 本地抓取助手 · 接口契约（v1）

> **这份契约是网页端与本地助手之间唯一的约定。**
> 两边可以独立开发，但**任何一方改了字段，必须先改这里**。
>
> 本地助手已实现：`crawler/agent/server.mjs`（实测 `/health` 返回 200）

---

## 为什么要有它

现在的抓取链路有 **7 个卡点**（要开终端 / 要 cd / 要 npm install / 要记参数 /
看不到进度 / 要去找文件 / 要手动导入）。目标是把前 6 个消掉，用户**只在网页上点一个按钮**。

**关键设计边界（不可违反）：**
1. **爬虫仍然跑在用户自己的电脑上** —— 不是服务端爬，和项目原有原则一致
2. **本地助手只监听 `127.0.0.1`**，不对外暴露
3. **本地助手永远不碰用户凭据** —— 它只回传岗位 JSON，**入库由网页端带着自己的 token 做**
4. **只接受工作台域名的请求**（Origin 白名单）

## 端点

基址：`http://127.0.0.1:8787`（可用 `node crawler/agent/server.mjs --port N` 改）

### `GET /health`

```json
{
  "ok": true,
  "service": "实习工作台 · 本地抓取助手",
  "crawler": "D:\\...\\crawler",
  "busy": null,
  "outputs": ["hikvision__实习-2026-10-02_1050.json"]
}
```

`busy` 为任务 id 时表示正在抓取（**一次只跑一个**，爬虫要开真浏览器，并行会互相踩）。

### `GET /sites`

```json
{ "sites": [ { "id": "hikvision", "name": "海康威视招聘",
               "needsLogin": false, "verified": "live", "kwSearch": false } ] }
```

**必须与 `crawler/sites.mjs` 同源**（服务端直接 import 它，禁止另写一份）。

### `POST /crawl`

请求：
```json
{ "sites": ["hikvision", "shixiseng"], "keyword": "实习",
  "pages": 1, "limit": 20, "mode": "all", "detail": 0 }
```

响应 `202`：
```json
{ "taskId": "a1b2c3d4", "command": "node run.mjs --site hikvision ..." }
```

**`command` 必须回传** —— 界面上要展示「它实际跑的是什么」，让用户看得见、也方便报错。

错误：
- `400` `{ "error": "sites 不能为空" }`
- `409` `{ "error": "已经有一个抓取在跑（<id>）" }` —— 并发时前端要提示而不是静默失败

### `GET /crawl/:taskId`

```json
{
  "id": "a1b2c3d4",
  "args": "--site hikvision --keyword 实习 --pages 1 ...",
  "state": "running | done | failed",
  "startedAt": 1759300000000,
  "endedAt": null,
  "log": ["▶ 海康威视招聘 · 实习", "第 1 页：读到 5 条", "..."],
  "error": null,
  "result": {
    "outputs": [
      { "file": "hikvision__实习-2026-10-02_1050.json",
        "site": "hikvision", "count": 5,
        "jobs": [ { "company": "", "title": "", "city": "", "salary": "", "url": "" } ] }
    ]
  }
}
```

**`result` 只在 `state === "done"` 时非 null。**
**`log` 是给界面实时显示的** —— 这是消掉「看不到跑到哪了」那个卡点的关键。

## 网页端要做什么

1. **探测**：页面加载时 `GET /health`。
   - 通 → 显示「本地助手已连接」+「开始抓取」按钮可点
   - 不通 → 按钮置灰，**并给出可复制的启动命令** `npm run agent`（别只说「未连接」）
2. **发起**：点按钮 → `POST /crawl`
3. **轮询**：每 1 秒 `GET /crawl/:id`，把 `log` 实时显示出来
4. **入库**：`state === "done"` 后，把 `result.outputs[].jobs` **拼成现有的导入文本格式**，
   走**已有的「批量导入」逻辑**（不要另写一套入库代码）
5. **失败可读**：把 `error` 和最后若干行 `log` 一起显示

### 现有的导入格式（必须复用，不要另造）

```
公司：某某科技
岗位：后端开发实习生
工作地点：深圳
薪资：180-250/天
https://example.com/job/123

---

（第二个岗位……）
```

## 测试要求

- **契约测试**：本地助手的响应结构必须有断言（字段名、类型、`state` 取值）
- **不许真跑爬虫的测试**：单测用 mock，别在 CI 里开真浏览器
- **验证 `command` 字段**：它必须与实际 `spawn` 的参数一致（防止界面显示的和真跑的不一样）
